## Overview  
This repository demonstrates the **SOLID principles** of object-oriented design through **concrete Python examples**. Each principle is illustrated with:  
- ❌ A **problematic code snippet** (violating the principle).  
- ✅ A **refactored solution** (applying the principle correctly).  
- 💡 **Key takeaways** for real-world projects.  

Perfect for developers aiming to:  
✔️ Reduce technical debt.  
✔️ Improve code scalability.  
✔️ Write maintainable applications

## SOLID Principles

1. Single Responsibility Principle (SRP)
   - A class should have only one reason to change, meaning that a class should only have one job or responsibility.
2. Open/Closed Principle (OCP)
   - Software entities (classes, modules, functions, etc.) should be open for extension but closed for modification.
3. Liskov Substitution Principle (LSP)
   - Objects of a superclass should be replaceable with objects of a subclass without affecting the correctness of the program.             
4. Interface Segregation Principle (ISP)
   - Clients should not be forced to depend on interfaces they do not use. Instead of one large interface, multiple smaller interfaces are preferred.
5. Dependency Inversion Principle (DIP)
   - High-level modules should not depend on low-level modules. Both should depend on abstractions (e.g., interfaces).
   - Abstractions should not depend on details. Details (concrete implementations) should depend on abstractions.
